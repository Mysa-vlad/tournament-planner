# DEFENSE — Завдання 3: Тестування

**PR:** [Mysa-vlad/tournament-planner#3](https://github.com/Mysa-vlad/tournament-planner/pull/3) · Spec: [spec-lab3.md](spec-lab3.md) · Аудит:

**1. Що я просив у AI.** Покрити застосунок із Завдання 2 тестами всіх рівнів (unit,
інтеграційні на справжній БД + HTTP, E2E на зібраному процесі), запустити Stryker,
класифікувати вижилих мутантів і підсилити слабкі тести окремими комітами. Промпт:
[`ai/05-lab3-prompt.md`](ai/05-lab3-prompt.md).

| 1   | помилка коду всередині транзакції поверталась як **503 «БД недоступна»** (spec-lab2 §4)        | `ai/06` #1 · червоний тест `7f2ee58` · spec `cdf2fb7` | `7ab7e69`            |

**Аналіз ефективності тестів.**

| Метрика                    | Тести Завдання 2 | Після Завдання 3                                     |
| -------------------------- | ---------------- | ---------------------------------------------------- |
| тестів                     | 9                | 134 (+1 E2E)                                         |
| покриття гілок / рядків    | 67 % / 88 %      | **93 % / 99 %**                                      |
| mutation score (Stryker)   | —                | 80.4 % → **89.7 %** (4 прогони)                      |
| вижилих: реальних прогалин | —                | 0 (60 класифіковано: 11 еквівалентних, 54 прийнятні) |

Головний висновок: висока покритість не дорівнює ефективності. Уже в прогоні 1 покриття
рядків було близько 98 %, а 111 мутантів вижили. Тести виконували код, але перевіряли
кількість записів і щасливий шлях, а не правила: доступ, «той самий» рахунок, межі,
інваріанти. Покриття під правила давали саме негативні тести на межах (T5) і тести
інваріантів (T6). Два реальні баги в коді (#1, #2) знайшли інший рівень тестів і мутант.

**3. Ключове рішення:** Vitest замість `node:test`, бо Stryker має для нього офіційний
runner з per-test coverage, а пороги покриття задаються per-glob. E2E проти окремого
процесу `node dist/server.js` із файловою БД і перезапуском
([`adr/0006`](adr/0006-test-tooling-vitest-stryker.md)).

**4. Перевірка (відтворення):**

- `npm test` дає 134 тести, а пороги T1/T2 виконано: модуль `standings` і `matches.domain`
  покрито на 100 %, глобально гілки ≥ 85 % ([`docs/evidence/14`](docs/evidence/14-coverage-final.md)).
- `npm run test:e2e` збирає застосунок і проганяє S1–S5 через окремий процес із перезапуском (AC14).
- **`npm run mutation`** дає звіт Stryker у `reports/mutation/index.html`. Динаміка:
  [`docs/evidence/12`](docs/evidence/12-mutation-progress.md); класифікація кожного вижилого:
  [`docs/evidence/13`](docs/evidence/13-survivors-classified.md)
  (`node scripts/classify-mutants.mjs reports/mutation/mutation.json`).
- pre-push запускає межі модулів, unit + інтеграційні з порогами й E2E (AC17).
