**3. Ключові рішення:**

- PGlite + сирий SQL через tagged template, без ORM: справжній PostgreSQL і ізольована база
  на кожен прогін без Docker. SQL лишається видимим для аудиту N+1
  ([`adr/0004`](adr/0004-postgres-pglite-raw-sql.md)).
- Composition root для ресурсів + AsyncLocalStorage для `requestId`/ініціатора/транзакції:
  сигнатури без «протягування», а `requestId` є в кожному лозі, зокрема з шару БД
  ([`adr/0005`](adr/0005-dependencies-composition-root-and-als.md)).

- `npm run probe:queries` → таблиця N+1; `npm run probe:edge` → крайові випадки
  (`docs/evidence/06` до, `07` після).
- Логи з `requestId`/`userId` на рівнях HTTP, сервісу й БД: `docs/evidence/08`.
- Межі шарів: SQL і драйвер БД лише в `src/db` і `*.repository.ts`. Це перевіряє правило
