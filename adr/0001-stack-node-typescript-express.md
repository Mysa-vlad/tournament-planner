# 0001. Стек: Node.js 22 + TypeScript + Express 5

- Status: accepted
- Date: 2026-11-14

## Context

Потрібен стек для REST API, який проживе 5 завдань курсу: БД (2), тести (3), CI/CD (4),
профілювання й винесення бібліотеки з «типізованим контрактом» (5).

## Decision Drivers

- завдання 5 вимагає типізованого контракту бібліотеки;
- hook має містити реальний крок «збірка»;
- знайомий фреймворк, щоб не витрачати час курсу на вивчення нового;
- Node 22 LTS уже встановлено.

## Considered Options

1. JavaScript (ESM) + Express 5
2. TypeScript + Express 5
3. TypeScript + NestJS

## Decision

Обрано **TypeScript + Express 5**. Він дає типізовані контракти між модулями (драйвер 1) і
справжній крок збірки `tsc` (драйвер 2). Express я вже знаю (драйвер 3).

## Pros and Cons of the Options

### JavaScript + Express 5

- 👍 нуль конфігурації, швидкий старт
- 👎 немає контрактів між модулями: помилки меж видно лише в рантаймі
- 👎 немає кроку «збірка», тож hook перевіряв би порожній крок

### TypeScript + Express 5

- 👍 типи як контракт публічного API модуля (`index.ts`)
- 👍 `tsc` — реальна збірка і швидкий typecheck у pre-commit
- 👎 додаткова конфігурація (tsconfig, typescript-eslint), а запуск у dev потребує `tsx`

### TypeScript + NestJS

- 👍 модулі і DI «з коробки»
- 👎 фреймворк сам диктує структуру, тож вивести її зі spec не вийде (суперечить меті завдання 1)
- 👎 високий поріг входу, багато магії декораторів

## Consequences

- Позитивні: межі модулів мають і типовий контракт, і перевірку dependency-cruiser.
- Негативні: збірка в `dist/` і два tsconfig (`tsconfig.json` для IDE/тестів,
  `tsconfig.build.json` для збірки).
- Далі: DI для завдання 5 робимо вручну (фабрики), без контейнера.
