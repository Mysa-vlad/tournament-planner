# 0004. БД: PostgreSQL (PGlite локально) + сирий SQL через tagged templates, без ORM

- Status: accepted
- Date: 2026-11-14

## Context

Завдання 2 замінює статичні дані реальною БД із транзакціями, валідацією, обробкою збоїв і
ідемпотентністю. Курс радить ізольоване локальне середовище (окрема база на прогін/гілку, не
спільний `localhost:5432`) і SQL tagged templates для сирого SQL. На машині розробника немає
ні PostgreSQL, ні Docker.

## Decision Drivers

- реляційні інваріанти (FK, UNIQUE, CHECK) і транзакції — прямо в БД;
- ізольована база на кожен прогін тестів без зовнішнього сервера;
- SQL видно в коді: N+1 і плани запитів легко аудитувати;
- той самий діалект, що й у продакшені (завдання 4).

## Considered Options

1. PostgreSQL через `pg` + Docker
2. PGlite (PostgreSQL 17, скомпільований у WASM, у процесі) + сирий SQL
3. SQLite (`node:sqlite`)
4. Prisma / Drizzle (ORM)

## Decision

Обрано **PGlite + сирий SQL через власний тег `sql`**. Це справжній PostgreSQL-діалект і
транзакції, а `memory://` дає окрему базу на кожен прогін (драйвери 1, 2, 4). Доступ до БД
захований за інтерфейсом `Database` (`src/db/database.ts`), тож у завданні 4 його можна
замінити на пул `pg` до керованого Postgres без змін у репозиторіях.

## Pros and Cons of the Options

### `pg` + Docker

- 👍 продакшн-конфігурація, справжній пул з'єднань
- 👎 Docker не встановлено, а спільний `localhost:5432` суперечить рекомендації курсу про ізоляцію

### PGlite

- 👍 нуль інфраструктури: `npm ci` і готово; `memory://` дає ізольовану базу на прогін
- 👍 повний PostgreSQL: `ON CONFLICT`, `RETURNING`, `unnest`, CHECK, транзакції
- 👎 одне з'єднання (немає пулу), а запити серіалізуються; для навантаження завдання 5 потрібен `pg`
- 👎 WASM-старт ~1 с на кожну базу

### SQLite (`node:sqlite`)

- 👍 вбудований у Node 22, найшвидший старт
- 👎 інший діалект і типи; в продакшені буде Postgres, тож запити довелося б переписувати

### ORM (Prisma / Drizzle)

- 👍 типізовані запити, міграції з коробки
- 👎 Prisma ховає SQL, тож N+1 і транзакції стають менш видимими (а це предмет аудиту)
- 👎 додатковий шар і кодогенерація для 5 таблиць; курс прямо радить tagged templates

## Consequences

- Позитивні: SQL і транзакції зосереджені в `src/db` і `*.repository.ts` (D6, перевіряється).
  Тести на БД не потребують сервера.
- Негативні: маплінг `snake_case → camelCase` пишеться вручну. Пулу немає, тож рекомендацію
  «пул + `SELECT now()`» виконано частково: явна ініціалізація й `SELECT now()` є (AC8), пулу
  поки немає.
- Далі: завдання 4 додасть адаптер `pg.Pool` за тим самим інтерфейсом `Database`.
