**3. Ключове рішення:** модульний моноліт за доменами з публічним `index.ts` і межами, які
автоматично перевіряє dependency-cruiser. Шари MVC «розмазують» модуль spec по теках, тож
межу між модулями неможливо перевірити правилом. Мікросервіси надмірні для MVP
([`adr/0003`](adr/0003-modular-monolith-by-domain.md)). Також:
[`adr/0001`](adr/0001-stack-node-typescript-express.md) (TS + Express 5) і
[`adr/0002`](adr/0002-quality-pipeline-husky-lint-staged.md) (husky + lint-staged).

**4. Перевірка:**

- Відтворюваний прогін на чистому клоні: `npm ci && npm run check` дає exit 0 (формат, лінт,
  типи, `audit:deps` ✔ 0 порушень, smoke 2/2, збірка) на `a9acb93`. AC1.
- Hook блокує брудний коміт: неформатований код, помилки ESLint і неправильне повідомлення
  коміту дають exit 1, і коміт не створюється
  ([`docs/evidence/01`](docs/evidence/01-dirty-commit-blocked.txt)). AC5.
- Pre-push заблокував push першої версії структури, бо знайшов 4 порушення D1/D2
  ([`02`](docs/evidence/02-push-blocked-by-dependency-rules.txt)). Після аудиту push
  проходить ([`03`](docs/evidence/03-push-passes-after-audit.txt)). AC4.
- Узгодженість `spec.md` ↔ структура: кожен модуль §3 є текою `src/modules/<name>/` з
  `index.ts` (AC3). Граф імпортів збігається з графом §3: це перевіряє `audit:deps` (D1–D5).
