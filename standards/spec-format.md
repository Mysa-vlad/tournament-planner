# Формат spec

`spec.md` — це **вхід** для роботи (зокрема для AI), а не документація постфактум.
Обсяг: **до однієї сторінки** на завдання. Якщо не влазить, ділимо на `spec-<тема>.md`.

## Обов'язкові розділи (у цьому порядку)

1. **Намір** — 2–4 речення: яку проблему вирішуємо і для кого.
2. **Поза обсягом** — що свідомо НЕ робимо в цій ітерації (і чому, одним реченням).
3. **Модулі та взаємодія** — список модулів з однорядковою відповідальністю + діаграма
   залежностей (Mermaid). Напрям стрілки = «залежить від».
4. **Дані та зв'язки** — ER-діаграма (Mermaid `erDiagram`) + інваріанти даних.
5. **Ключові сценарії** — для кожного: тригер → кроки → які дані змінюються.
6. **Правила залежностей** — нумеровані правила `D1, D2, …`, які перевіряються
   автоматично (`npm run audit:deps`).
7. **Критерії прийняття** — нумеровані `AC1, AC2, …`; кожен критерій перевіряємий
   (команда, тест або конкретний пункт рев'ю).

## Правила

- Кожен критерій має ідентифікатор — на нього посилаються коміти, аудит і DEFENSE.
- Розбіжність, знайдена в аудиті, виправляється **зміною spec** (новий/уточнений
  критерій чи правило), а потім кодом. Ручний патч без зміни spec заборонений.
- Мова — українська; ідентифікатори коду — англійською.
